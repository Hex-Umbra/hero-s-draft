# P-42 tranche 3 — Sanctifié, Carnage, Marque : les neuf passifs jouables — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development (méthode fixée par l'orchestrateur). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** les trois derniers lots (Sanctifié, Carnage, Marque) arrivent et démasquent leur passif ; *Marque du Mage* se déclenche sur la première carte de dégâts à cible unique du tour, Attaque ou Compétence, qui ne tue pas sa cible ; *Prière* pose le statut neuf `hp_regen`, la Source de Vie.

**Architecture :** un déclencheur neuf, `RelicTrigger.onDamagingCardPlayed`, envoyé par la suite commune `_afterCardPlayed` quand la vue effective de la carte porte un effet `damage` (`EffectiveCard.dealsDamage`) ; `MageMarkPassive` l'écoute et tient pour absente une cible à 0 PV ; `hp_regen` se joue dans les deux processeurs de statuts sur le modèle de `mana_regen`, après le tic, jamais sur un porteur à 0 PV ; le nom du statut que lit `targetStatus` passe par une clé ARB à sélection ; le reste est de la donnée — six `git mv`, dix fichiers, deux `feeds`, trois lignes de `pubspec.yaml` —, le démasquage compris (O5).

**Tech Stack :** Flutter, Flame 1.17, Riverpod 2.5 (`Notifier`), `flutter_test`, ARB + `flutter gen-l10n`.

**Spec :** `docs/superpowers/specs/2026-11-18-p42-tranche-3-design.md`, en entier (spec §10 : un seul plan). Arbitrages A1 à A20 et réponses du propriétaire (A3 (c), A4 (ii), le texte de *Marque du Mage*, D-1/A19 en (b), « Source de Vie » / « Life Spring », les cartes de §3.2) : spec §1.2, §1.3 ; options écartées : `…-design-verifications.md` §1. **Ne rouvrir aucun de ces arbitrages.**

## Review Focus

Les cinq modes d'échec les plus probables qu'aucun test ne garde encore ; chacun a son test dans la tâche nommée.

1. **La cible tuée consomme la marque** (A4 (ii)) : l'ennemi abattu est encore dans `enemies`, à 0 PV, quand le passif se résout (`cleanDeadEnemies` vient après, `combat_controller.dart:324`), et la stratégie ne cherche que l'absence (`passive_strategies.dart:77`) — le joueur perdrait la marque du tour pour avoir tué. → **Task 2**, `une cible tuee par la carte ne consomme pas la marque`.
2. ***Nova* marque ou consomme** (A3 (c)) : la vue évoluée prend la cible de groupe de *Nova* (`signature_instance.dart:141-145`) et `playSignature` ne transmet `enemyId` qu'à une signature à cible unique (`:251`, `:287`) ; un déclencheur qui lirait la cible de la donnée, ou une sélection restante, ferait marquer la signature de groupe. → **Task 2**, test neuf de `combat_signature_test.dart`.
3. **La Source de Vie relève un mort** (A6) : le Feu ou le Poison du même début de tour tuent, puis le soin rend des PV ; côté ennemi, le tic et le déclin sont une seule expression (`status_effect_processor.dart:141`), où le soin doit s'insérer après le tic. → **Task 3**, les deux tests « que son Poison tue ».
4. **La Faiblesse de *Sommation* réduit une attaque de moins que prévu** (A19) : un ennemi vieillit ses statuts au début de sa phase, avant d'agir ; une durée N réduit N − 1 attaques, d'où les durées de §3.2 allongées d'un tour. → **Task 6**, `Sommation : la Faiblesse reduit les deux attaques suivantes`.
5. **La Puissance du Paladin va à l'Armure de *Réprimande*, ou deux fois** (Q11) : seul le premier `apply_status` d'une carte reçoit la Puissance de statut ; l'Armure, premier effet, n'en reçoit aucune. → **Task 6**, `Reprimande : … la Puissance du Paladin sur la Faiblesse seule`.
