Chapitre 14

L'économie : or, boutique, forge et fusion

L'or est la seule monnaie du jeu, et il n'achète que quatre choses : des cartes, de la vie, de la place et de la puissance. Voici les barèmes exacts et les algorithmes de tirage.

Dans ce chapitre

  2. La boutique : inventaire et services
  3. Le prix d'une carte

  7. La forge du feu de camp et les slots bonus

Beaucoup de jeux ont trois ou quatre monnaies : de l'or, des gemmes, des fragments, des jetons d'événement. Hero's Draft n'en a qu'une. Un seul entier, gold, vit dans InventoryState, et toutes les dépenses du jeu passent par une seule méthode, spendGold. C'est une contrainte de design forte, et elle simplifie énormément le code : il n'existe aucun endroit dans le projet où une devise peut être créée ou détruite en douce.

Ce chapitre suit l'or de bout en bout. D'abord sa production (combat, événements, départ de partie), puis ses quatre débouchés : la boutique (cartes, soin, purge, extension, clonage), la forge du feu de camp (runes et slots bonus), la forge de fusion (fusion de runes) et, indirectement, la fusion de cartes qui, elle, ne coûte pas d'or mais consomme trois exemplaires d'une carte.

Au passage, nous démonterons les deux algorithmes de tirage les plus denses du projet : _rollRarity (quelle rareté une carte de boutique reçoit-elle ?) et _rollUpgradeId + _rollWeighted (quelle rune tombe, et à quel niveau ?). Ils tiennent tous les deux dans Riverpod lib/game/controllers/shop_controller.dart, le fichier central de ce chapitre.

À retenir

Quatre fichiers portent 95 % de l'économie : lib/game/controllers/shop_controller.dart (prix et tirages), lib/models/shop_state.dart (le prix du clonage), lib/game/controllers/inventory_controller.dart (le porte-monnaie) et lib/game/controllers/run/gold_manager.dart (les slots de forge bonus). Tout le reste n'est que de l'interface.

1. L'or — d'où il vient, où il part

Une partie commence avec exactement 50 or. C'est écrit en dur dans startNewRun, la méthode qui remet à zéro l'intégralité de l'état d'une run.

lib/game/controllers/run_controller.dartdart
  /// Démarre une nouvelle partie avec la classe choisie
  void startNewRun(HeroData chosenClass, [PassiveData? activePassive]) {
    // ...
    // Réinitialise l'inventaire avec 50 d'or de départ
    ref
        .read(inventoryProvider.notifier)
        .reset(
          initialGold: 50,
          initialRelics: const [],
          initialBonusShopCards: 0,
        );

    // Réinitialise les cooldowns de sorts
    ref.read(skillProvider.notifier).resetCooldowns();
  }

Notez le troisième paramètre : initialBonusShopCards: 0. Les extensions de boutique achetées lors de la partie précédente ne sont pas conservées — nous y reviendrons en section 2.

Le porte-monnaie : deux méthodes, un contrat

Le InventoryController est un Notifier Riverpod minuscule. Toute l'économie repose sur ces deux méthodes de sept lignes :

lib/game/controllers/inventory_controller.dartdart
  void gainGold(int amount) {
    state = state.copyWith(gold: state.gold + amount);
  }

  bool spendGold(int amount) {
    if (state.gold < amount) return false;
    state = state.copyWith(gold: state.gold - amount);
    return true;
  }

Le contrat de spendGold est le point le plus important de tout le chapitre : la vérification et le débit sont dans la même méthode. Si les fonds sont insuffisants, rien n'est débité et la méthode renvoie false. Le solde ne peut donc jamais devenir négatif, et il n'existe aucun chemin de code capable d'acheter « à crédit ».

Règle du jeu

Aucun achat n'est jamais fait à crédit. Chaque appelant écrit le même motif : if (inventoryController.spendGold(price)) { … applique l'effet … }. L'effet n'est appliqué que si le paiement a réussi. C'est vrai pour l'achat de carte, le soin, la purge, l'extension, le clonage, le reroll de forge, l'achat de slot et la fusion de runes — sans exception.

Regardez la structure de buyCard : c'est le patron que vous retrouverez partout.

lib/game/controllers/shop_controller.dartdart
  /// Achète une carte spécifique de la boutique
  bool buyCard(CardInstance card, int price) {
    final inventoryController = ref.read(inventoryProvider.notifier);
    final deckNotifier = ref.read(deckProvider.notifier);
    if (inventoryController.spendGold(price)) {
      state = state.copyWith(
        cardsForSale: state.cardsForSale.where((c) => c.uniqueId != card.uniqueId).toList(),
      );
      deckNotifier.addCardToMasterDeck(card);
      return true;
    }
    return false;
  }

La carte n'est retirée de l'étal et ajoutée au deck que dans la branche « paiement réussi ». La valeur de retour remonte jusqu'à l'écran, qui affiche soit « Acheté ! » soit « Or insuffisant ». Aucun état intermédiaire n'existe.

Le butin de combat

La deuxième source d'or, et de loin la principale, c'est la victoire au combat. Le calcul vit dans RewardController.handleVictory, juste après le calcul de l'XP, et suit exactement la même forme :

lib/game/controllers/reward_controller.dartdart
    // 2. Calculate Gold from defeated enemies
    int totalGold = 0;
    for (var enemy in defeatedEnemies) {
      final double levelMultiplier = 1.0 + 0.10 * (enemy.stats.level - 1);
      totalGold += (enemy.data.gold * levelMultiplier).round();
    }
    if (currentNode.bossRewardType == BossRewardType.doubleXp) {
      totalGold *= 3;
    }

Trois choses à lire dans ces huit lignes :

  1. La base est enemy.data.gold, la valeur écrite dans assets/data/enemies.json. Le bestiaire ne compte que quatre entrées.
  2. Le multiplicateur de niveau est linéaire : 1 + 0,10 × (niveau − 1). Un ennemi de niveau 1 rapporte sa valeur de base, un ennemi de niveau 11 rapporte le double.
  3. L'arrondi est fait par ennemi (.round() dans la boucle), pas sur le total. Deux gobelins de niveau 4 rapportent round(12 × 1,3) × 2 = 16 × 2 = 32, et non round(24 × 1,3) = 31.

Le ×3 mérite une explication. BossRewardType est un enum à trois valeurs (cards, doubleXp, improvedRelic) tiré au moment de la génération du boss. Malgré son nom, doubleXp ne double rien : il triple l'XP et l'or, et ajoute une carte bonus aléatoire. Un boss composé de deux orcs de niveau 10 sur un nœud doubleXp verse donc (48 + 48) × 3 = 288 or d'un coup — de quoi acheter une carte légendaire et un clonage.

Piège

Le nom doubleXp ment : le facteur appliqué est *= 3, à la fois pour l'XP (totalXp *= 3) et pour l'or (totalGold *= 3). Si vous ajustez l'équilibrage, cherchez la valeur littérale 3 dans reward_controller.dart, pas le mot « double ».

L'or n'est pas versé à la fin du combat : il est stocké dans RewardState.goldGained et n'atterrit dans l'inventaire que lorsque le joueur ramasse la récompense.

Point d'attention

C'est le seul appel à spendGold du projet dont la valeur de retour est ignorée. Si un jour quelqu'un déclenche un événement par script (test, triche de debug, cinématique) sans passer par isSelectable, le choix payant deviendra gratuit. Une ligne if (!inventoryController.spendGold(...)) break; supprimerait la dette.

2. La boutique : inventaire et services

La boutique est un nœud de carte (MapNodeType.shop) qui ouvre ShopScreen. L'écran est coupé en deux : à gauche (75 % de la largeur) les cartes en vente, à droite (25 %) cinq services. Les cartes sont générées une seule fois, à l'entrée, par initializeShop.

lib/game/controllers/shop_controller.dartdart
  /// Initialise la boutique avec une sélection aléatoire de cartes de jeu
  void initializeShop(List<CardData> allCards, int bonusShopCards) {
    final List<CardData> eligibleCards = _getEligibleCards(allCards);

    if (eligibleCards.isEmpty) {
      state = const ShopState(cardsForSale: [], purchasedHeal: false);
      return;
    }

    final rng = Random();
    final List<CardData> shuffled = List.from(eligibleCards)..shuffle(rng);
    final count = min(shuffled.length, 3 + bonusShopCards);

    final int act = ref.read(runProvider).act;
    final List<CardInstance> generatedInstances = shuffled
        .take(count)
        .map((cardData) => _generateShopCardInstance(cardData, act, rng))
        .toList();

    state = ShopState(
      cardsForSale: generatedInstances,
      purchasedHeal: false,
      cloneOptions: const [],
      clonePurchasedCount: 0,
    );
  }

L'inventaire fait donc 3 + bonusShopCards cartes, plafonné par la taille du pool éligible. Le mélange se fait sur les CardData — les « modèles » de cartes — donc deux exemplaires de la même carte ne peuvent pas apparaître dans la même boutique. Le pool éligible exclut deux catégories :

lib/game/controllers/shop_controller.dartdart
  List<CardData> _getEligibleCards(List<CardData> allCards) {
    return allCards
        .where((c) =>
            c.type != CardType.status &&
            c.rarity != CardRarity.unique)
        .toList();
  }

Les cartes de type status (les malédictions, blessures et autres cartes parasites) et les cartes unique ne sont jamais vendues. Avec les 17 cartes de assets/data/cards.json, toutes communes et non-status, le pool éligible fait 17 entrées : une boutique standard en montre 3.

Le soin : deux verrous, pas un

Le soin est le seul service à usage unique. Le verrou est dans le contrôleur, dès la première ligne :

lib/game/controllers/shop_controller.dartdart
  /// Achète un soin dans la boutique
  bool buyHeal(int price, int amount) {
    if (state.purchasedHeal) return false;

    final inventoryController = ref.read(inventoryProvider.notifier);
    final runController = ref.read(runProvider.notifier);
    if (inventoryController.spendGold(price)) {
      runController.heal(amount);
      state = state.copyWith(purchasedHeal: true);
      return true;
    }
    return false;
  }

L'écran ajoute un deuxième garde, qui n'est pas dans le contrôleur : si le héros est déjà à PV max, l'achat est refusé avant tout débit, avec une notification dédiée.

Ce garde protège le joueur d'un gaspillage : 30 or dépensés pour zéro PV rendu, puisque heal plafonne à maxPv. Le purchasedHeal n'est pas consommé non plus, donc la potion reste disponible plus tard dans la même boutique.

Le clonage : un prix qui double

Le prix du clonage n'est pas un littéral d'interface : c'est un getter de l'état, et il utilise un décalage de bits.

lib/models/shop_state.dartdart
class ShopState {
  final List<CardInstance> cardsForSale;
  final bool purchasedHeal;
  final List<CardInstance> cloneOptions;
  final int clonePurchasedCount;

  const ShopState({
    this.cardsForSale = const [],
    this.purchasedHeal = false,
    this.cloneOptions = const [],
    this.clonePurchasedCount = 0,
  });

  int get clonePrice => 150 << clonePurchasedCount;

150 << n se lit « 150 décalé de n bits vers la gauche », ce qui est une manière compacte et exacte d'écrire 150 × 2ⁿ. Pour un débutant, sachez simplement que le décalage à gauche d'un bit multiplie un entier par 2 : c'est le même résultat qu'une multiplication, en un seul cycle machine.

Le clonage duplique la carte instance, avec ses runes, dans une nouvelle instance qui reçoit un uniqueId tout neuf (généré par le constructeur de CardInstance) :

lib/game/controllers/shop_controller.dartdart
  /// Duplique une carte sélectionnée contre paiement (Miroir Magique)
  bool cloneCard(CardInstance card) {
    final price = state.clonePrice;
    final inventoryController = ref.read(inventoryProvider.notifier);
    final deckNotifier = ref.read(deckProvider.notifier);
    if (inventoryController.spendGold(price)) {
      deckNotifier.addCardToMasterDeck(
        CardInstance(
          data: card.data,
          rarity: card.rarity,
          forgeUpgrades: List.from(card.forgeUpgrades),
        ),
      );
      state = state.copyWith(
        clonePurchasedCount: state.clonePurchasedCount + 1,
      );
      return true;
    }
    return false;
  }

Le List.from(card.forgeUpgrades) est important : forgeUpgrades est une liste non modifiable dans CardInstance, et la copie garantit que les deux exemplaires ne partagent pas la même référence. Cloner une carte légendaire portant trois runes duplique donc les trois runes — c'est l'achat le plus puissant du jeu, et c'est pour cela qu'il coûte 150 puis double à chaque fois.

3. Le prix d'une carte

Le prix des cartes, lui, n'est pas dans l'interface : c'est une méthode static du contrôleur de boutique. Statique, parce qu'elle ne dépend d'aucun état — seulement de la carte qu'on lui passe. C'est une fonction pure de 24 lignes.

lib/game/controllers/shop_controller.dartdart
  /// Helper pour calculer le prix d'une carte selon sa rareté et ses upgrades (+20 Or par upgrade)
  static int getCardPrice(CardInstance card) {
    int basePrice;
    switch (card.rarity) {
      case CardRarity.common:
        basePrice = 25;
        break;
      case CardRarity.uncommon:
        basePrice = 50;
        break;
      case CardRarity.rare:
        basePrice = 100;
        break;
      case CardRarity.epic:
        basePrice = 150;
        break;
      case CardRarity.legendary:
        basePrice = 200;
        break;
      case CardRarity.unique:
        basePrice = 999;
        break;
    }
    return basePrice + (card.forgeUpgrades.length * 20);
  }

Deux termes, pas un de plus : un prix de base par rareté, plus 20 or par rune de forge présente sur la carte. Notez bien que c'est le nombre de runes qui compte (forgeUpgrades.length), pas leur niveau. Une carte portant sharp:3 coûte le même supplément qu'une carte portant sharp:1 : 20 or.

4. Comment la boutique fabrique ses cartes

Nous arrivons au cœur du chapitre. Une carte de boutique n'est pas la copie conforme de son CardData : c'est une CardInstance fabriquée à la volée, dont la rareté et les runes sont tirées au sort en fonction de l'acte courant. Toute la fabrication tient dans _generateShopCardInstance.

lib/game/controllers/shop_controller.dartdart
  /// Helper privé réalisant la génération complète d'une instance de carte pour la boutique
  CardInstance _generateShopCardInstance(CardData data, int act, Random rng) {
    final finalRarity = _rollRarity(data.rarity, act, rng);

    var instance = CardInstance(
      data: data,
      rarity: finalRarity,
    );

    final int rarityIndex = CardRarity.values.indexOf(finalRarity);
    final int maxUpgrades = data.baseMaxForgeUpgrades + rarityIndex;

    int upgradesToRoll = 0;
    final rollUpgrade = rng.nextInt(100);
    if (act == 2) {
      if (rollUpgrade < 15) {
        upgradesToRoll = 1;
      }
    } else if (act >= 3) {
      if (rollUpgrade < 10) {
        upgradesToRoll = 2;
      } else if (rollUpgrade < 40) {
        upgradesToRoll = 1;
      }
    }

    if (upgradesToRoll > maxUpgrades) {
      upgradesToRoll = maxUpgrades;
    }

    if (upgradesToRoll > 0) {
      final List<String> upgrades = [];
      for (int i = 0; i < upgradesToRoll; i++) {
        final newUpgrade = _rollRandomUpgrade(instance, upgrades, rng);
        upgrades.add(newUpgrade);
      }
      instance = instance.copyWith(forgeUpgrades: upgrades);
    }

    return instance;
  }

La méthode se lit en quatre temps :

  1. Rareté — _rollRarity(data.rarity, act, rng) peut faire monter la carte d'un ou deux crans.
  2. Capacité — maxUpgrades = baseMaxForgeUpgrades + rarityIndex, calculée après le tirage de rareté : monter en rareté augmente la capacité de runes.
  3. Nombre de runes — un seul rng.nextInt(100), interprété différemment selon l'acte, puis écrêté par la capacité.
  4. Tirage des runes — _rollRandomUpgrade autant de fois que nécessaire, en passant la liste déjà tirée pour éviter les doublons.

Le tirage de rareté

lib/game/controllers/shop_controller.dartdart
  /// Helper pour tirer la rareté finale d'une carte selon l'acte
  CardRarity _rollRarity(CardRarity baseRarity, int act, Random rng) {
    if (baseRarity == CardRarity.unique) return baseRarity;

    int increase = 0;
    final roll = rng.nextInt(100);
    if (act == 1) {
      if (roll < 10) {
        increase = 1;
      }
    } else if (act == 2) {
      if (roll < 25) {
        increase = 1;
      }
    } else {
      if (roll < 10) {
        increase = 2;
      } else if (roll < 50) {
        increase = 1;
      }
    }

    if (increase == 0) return baseRarity;

    final rarities = CardRarity.values;
    int baseIndex = rarities.indexOf(baseRarity);
    int targetIndex = baseIndex + increase;

    int maxIndex = rarities.indexOf(CardRarity.legendary);
    if (targetIndex > maxIndex) {
      targetIndex = maxIndex;
    }

    return rarities[targetIndex];
  }

Le motif rng.nextInt(100) puis des seuils < en cascade est le générateur de probabilités le plus courant du projet. nextInt(100) renvoie un entier uniforme dans [0, 99], donc « roll < 10 » vaut exactement 10 chances sur 100. Attention à la lecture des cascades : en acte 3, roll < 50 n'est évalué que si roll < 10 a échoué. Les 40 % de « +1 rareté » correspondent donc aux valeurs 10 à 49.

Règle du jeu

Le plafond de _rollRarity est legendary, pas unique : la ligne int maxIndex = rarities.indexOf(CardRarity.legendary); écrête targetIndex. Une carte de base légendaire reste légendaire, quel que soit l'acte.

Le tirage du nombre de runes

Le deuxième tirage, rollUpgrade, suit exactement le même motif. Il n'y a aucune rune en acte 1 : le bloc if (act == 2) … else if (act >= 3) … ne comporte pas de branche pour l'acte 1, donc upgradesToRoll reste à sa valeur initiale, 0.

Attention au dernier écrêtage : if (upgradesToRoll > maxUpgrades) upgradesToRoll = maxUpgrades;. Avec baseMaxForgeUpgrades = 1 pour toutes les cartes du jeu, une carte restée commune a une capacité de 1. Les 10 % de « deux runes » de l'acte 3 sont donc ramenés à une seule rune une fois sur deux, quand le tirage de rareté n'a rien donné.

Les deux tirages étant indépendants (deux appels distincts à rng.nextInt(100)), on peut multiplier les probabilités. En acte 3, la probabilité qu'une carte sorte réellement avec deux runes vaut :

L'ordre de calcul est : valeur de base × multiplicateur de rareté (arrondi), puis ajout des runes. Une Frappe légendaire (6 dégâts, ×2,0) avec sharp:2 inflige round(6 × 2,0) + 4 = 16 dégâts, et non round((6 + 4) × 2,0) = 20. Les runes ne bénéficient jamais du multiplicateur de rareté.

6. Le tirage pondéré des runes

Nous savons maintenant combien de runes une carte reçoit. Reste la question la plus intéressante : lesquelles. Le tirage se fait en trois étages, tous dans shop_controller.dart :

  1. _rollUpgradeId choisit un pool en fonction de la rareté de la carte, puis descend dans les pools de repli si le pool visé est vide.
  2. _getEligibleUpgradesForPool filtre le pool par type de carte, par requiresExhaust et par doublons.
  3. _rollWeighted tire une rune dans la liste filtrée, proportionnellement au champ weight.

Étage 1 : choisir le pool

lib/game/controllers/shop_controller.dartdart
  /// Helper privé pour tirer un ID d'upgrade aléatoire compatible
  String? _rollUpgradeId(CardInstance card, Random rand, List<String> excludedIdsInCurrentRolls) {
    final r = rand.nextInt(100);
    String targetPool;
    if (card.rarity == CardRarity.common) {
      targetPool = 'common';
    } else if (card.rarity == CardRarity.uncommon) {
      targetPool = r < 75 ? 'common' : 'uncommon';
    } else {
      targetPool = r < 65 ? 'common' : (r < 90 ? 'uncommon' : 'rare');
    }

    List<String> poolOrder = ['rare', 'uncommon', 'common'];
    int startIndex = poolOrder.indexOf(targetPool);
    if (startIndex == -1) startIndex = 2;

    for (int i = startIndex; i < poolOrder.length; i++) {
      final pool = poolOrder[i];
      final eligibleIds = _getEligibleUpgradesForPool(card, pool, excludedIdsInCurrentRolls);
      if (eligibleIds.isNotEmpty) {
        return _rollWeighted(eligibleIds, rand);
      }
    }

    for (final pool in poolOrder) {
      final eligibleIds = _getEligibleUpgradesForPool(card, pool, excludedIdsInCurrentRolls);
      if (eligibleIds.isNotEmpty) {
        return _rollWeighted(eligibleIds, rand);
      }
    }
    return null;
  }

poolOrder = [ rare , uncommon , common ] 0 1 2 targetPool = 'rare' → startIndex = 0 → essaie rare, puis uncommon, puis common targetPool = 'uncommon' → startIndex = 1 → essaie uncommon, puis common targetPool = 'common' → startIndex = 2 → essaie common uniquement

Le repli est donc à sens unique : on ne remonte jamais vers un pool plus rare… sauf si la première boucle échoue complètement. Dans ce cas, la seconde boucle rebalaie tout poolOrder depuis le début, c'est-à-dire en commençant par rare. Ce filet de sécurité n'est pas théorique, nous allons le voir.

    final eligible = <String>[];
    for (final upgrade in registry.forgeUpgrades) {
      if (!upgrade.pools.contains(poolName)) continue;

      final alreadyInRolls = currentRolls.any((u) => u.split(':')[0] == upgrade.id);
      if (alreadyInRolls) continue;

      // Exclusions spécifiques au type de carte:
      if (upgrade.eligibleCardTypes != null &&
          !upgrade.eligibleCardTypes!.contains(card.data.type.name)) {
        continue;
      }

      if (upgrade.requiresExhaust && !card.data.isExhaust) {
        continue;
      }

      eligible.add(upgrade.id);
    }
    return eligible;
  }

Étage 3 : la roue de la fortune

lib/game/controllers/shop_controller.dartdart
  String _rollWeighted(List<String> eligibleIds, Random rand) {
    int totalWeight = 0;
    final upgrades = <ForgeUpgradeData>[];
    for (final id in eligibleIds) {
      final upg = ForgeUpgradeData.getById(id);
      if (upg != null) {
        upgrades.add(upg);
        totalWeight += upg.weight;
      }
    }

    if (totalWeight == 0 || upgrades.isEmpty) {
      return eligibleIds[rand.nextInt(eligibleIds.length)];
    }

    int choice = rand.nextInt(totalWeight);
    int currentSum = 0;
    for (final upg in upgrades) {
      currentSum += upg.weight;
      if (choice < currentSum) {
        return upg.id;
      }
    }
    return upgrades.last.id;
  }

C'est l'algorithme de tirage pondéré classique, en deux passes. La première additionne les poids ; la seconde tire un nombre dans [0, totalWeight − 1] et avance une somme cumulée jusqu'à la dépasser. Imaginez une règle graduée découpée en segments proportionnels aux poids : on lance une fléchette et on regarde dans quel segment elle tombe.

illustrationtext
Carte d'attaque, pool common — totalWeight = 440

 0        100        200      280      360      440
 |--sharp--|-hardened-|-burning|freezing|shocking|
    22,7 %    22,7 %    18,2 %   18,2 %   18,2 %

choice = rand.nextInt(440) = 265  →  265 < 280  →  "burning"

Deux détails d'implémentation qui comptent. D'abord, le repli if (totalWeight == 0 || upgrades.isEmpty) retombe sur un tirage uniforme : ce cas ne se produit que si toutes les runes éligibles ont un poids de 0 ou si le registre est incomplet. Ensuite, le return upgrades.last.id final est inatteignable en théorie (la somme cumulée finit toujours par dépasser choice) mais indispensable en pratique : Dart exige que toute fonction non void retourne quelque chose sur tous les chemins.

Le niveau de la rune

Une fois l'identifiant tiré, il ne reste qu'à choisir le niveau. C'est le rôle de _rollRandomUpgrade, qui assemble aussi la chaîne finale :

lib/game/controllers/shop_controller.dartdart
  /// Helper privé pour générer un upgrade de forge aléatoire avec son tier
  String _rollRandomUpgrade(CardInstance card, List<String> existingUpgrades, Random rng) {
    final excludedIds = existingUpgrades.map((u) => u.split(':')[0]).toList();
    String? rolledId = _rollUpgradeId(card, rng, excludedIds);
    rolledId ??= _rollUpgradeId(card, rng, []);
    rolledId ??= 'sharp';

    int tier = 1;
    if (rolledId != 'enduring') {
      final t = rng.nextInt(100);
      if (t < 80) {
        tier = 1;
      } else if (t < 95) {
        tier = 2;
      } else {
        tier = 3;
      }
    }
    return '$rolledId:$tier';
  }

Les trois premières lignes forment une cascade de replis élégante, écrite avec l'opérateur d'affectation conditionnelle ??= (« affecte seulement si la variable est nulle ») : on essaie d'abord sans doublon, puis en autorisant les doublons, et en dernier recours on retourne 'sharp'. La carte reçoit toujours une rune.

7. La forge du feu de camp et les slots bonus

La boutique vend des cartes déjà serties. La forge, elle, sertit une carte que vous possédez déjà. On y accède depuis un nœud Repos (le feu de camp) : on choisit une carte du deck maître, puis un dialogue plein écran propose plusieurs runes et on en garde une seule.

Le fichier est lib/ui/widgets/forge_upgrade_dialog.dart. Il commence par un petit modèle qui n'existe que le temps de la session de forge :

Combien de fentes voit-on ?

C'est la partie la plus intéressante : le nombre de propositions est lui aussi tiré au sort, par une cascade de probabilités décroissantes.

b) Fusion de runes : le nœud Forge de fusion

Ce nœud spécial (25 % de chance d'apparaître entre les étages 3 et 7, voir le chapitre 12) ne touche pas aux cartes : il compacte les runes d'une même carte. Deux sharp:1 occupent deux fentes ; un sharp:2 n'en occupe qu'une, pour le même effet total.

lib/ui/screens/forge_fusion_screen.dartdart
List<FusionOption> _getFusionsForCard(CardInstance card) {
  final Map<String, List<String>> groups = {};
  for (final upg in card.forgeUpgrades) {
    final id = upg.split(':')[0];
    groups.putIfAbsent(id, () => []).add(upg);
  }

  final fusions = <FusionOption>[];
  groups.forEach((id, list) {
    if (list.length >= 2) {
      int totalTier = 0;
      for (final upg in list) {
        final parts = upg.split(':');
        final tier = parts.length > 1 ? (int.tryParse(parts[1]) ?? 1) : 1;
        totalTier += tier;
      }
      final cost = 80 * (list.length - 1);
      fusions.add(FusionOption(
        upgradeId: id, originalUpgrades: list, totalTier: totalTier, cost: cost,
      ));
    }
  });
  return fusions;
}
Règle du jeu

Coût d'une fusion de runes : 80 × (nombre de runes fusionnées − 1). Deux runes → 80 or, trois runes → 160 or, quatre runes → 240 or. Le niveau résultant est la somme des niveaux, sans plafond.

Le circuit complet d'une rune

Quiz — vérifiez vos acquis

1. Combien coûte le troisième reroll d'une même fente de forge ?

  • 20 or, le prix est fixe
  • 60 or, soit 3 × 20
  • 31 or, soit round(20 × 1,25²)
  • 80 or, comme une fusion de runes
Réponse : ForgeSlot.rerollCost vaut (20 * pow(1.25, rerollsCount)).round(). Au moment du troisième reroll, rerollsCount vaut 2, donc 20 × 1,5625 = 31,25 → 31. Le compteur est propre à chaque fente.

2. Quel est le prix du troisième clonage de carte dans une même boutique ?

  • 450 or (150 × 3)
  • 600 or (150 << 2)
  • 300 or
  • 150 or, le prix ne change pas
Réponse : ShopState.clonePrice vaut 150 << clonePurchasedCount, soit un doublement à chaque achat : 150, 300, 600, 1 200… Le compteur est remis à zéro par clearCloneOptions() quand on quitte la boutique.

3. Sur combien de fentes une session de forge démarre-t-elle en moyenne, hors fentes achetées ?

  • 1 exactement — la première est la seule garantie
  • 3, une par niveau de rune possible
  • 5, le plafond affiché
  • 1,87 : la première est garantie, les suivantes ont 50 %, 25 %, 10 % et 2 % de chance
Réponse : _generateInitialSlots ajoute toujours la fente 1, puis évalue quatre tirages indépendants à 0,50 · 0,25 · 0,10 · 0,02. L'espérance vaut donc 1 + 0,87 = 1,87 fente.

4. Une carte porte burning:2 et burning:1. Que coûte leur fusion, et que donne-t-elle ?

  • 80 or, et elle donne burning:3
  • 160 or, et elle donne burning:3
  • 80 or, et elle donne burning:2 (le niveau le plus haut)
  • Gratuit, la fusion de runes ne coûte rien
Réponse : le coût est 80 * (list.length - 1), soit 80 or pour deux runes, et totalTier est la somme des niveaux, donc burning:3.

5. Combien coûte une carte rare portant deux runes de forge en boutique ?

  • 100 or — les runes sont offertes
  • 120 or
  • 140 or
  • 200 or
Réponse : ShopController.getCardPrice donne un prix de base de 100 pour une rare, plus card.forgeUpgrades.length * 20, soit 100 + 40 = 140 or.

6. Pourquoi bonusForgeSlots vit-il sur RunState et non dans l'état local du dialogue de forge ?

  • Pour pouvoir l'afficher dans la barre d'outils de la carte
  • Parce que l'achat est permanent pour toute la run : la fente reste disponible à tous les feux de camp suivants
  • Parce que le dialogue est reconstruit à chaque image
  • Pour que le prix augmente à chaque combat
Réponse : buyBonusForgeSlot() incrémente bonusForgeSlots sur RunState, qui est sérialisé dans la sauvegarde. L'investissement est donc permanent sur la run — et plafonné à 4 achats (50, 80, 120, 175 or).
