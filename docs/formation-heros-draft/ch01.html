1. Le jeu en trois minutes

Hero's Draft est un roguelike deckbuilder : un jeu de cartes au tour par tour où l'on construit son paquet au fil d'une partie, et où la mort remet tout à zéro.

Une partie — on dira une run — se déroule ainsi. Le joueur choisit une classe de héros (Paladin, Berserker ou Mage), puis compose un deck de départ en sélectionnant cinq cartes dans un pool commun ; les deux cartes propres à sa classe s'ajoutent automatiquement. Il arrive alors sur une carte du monde générée aléatoirement : un graphe de dix étages, parcouru du bas vers le haut, où chaque nœud est une rencontre.

Combat

Des ennemis, un tour à jouer avec les cartes de sa main et le mana disponible. Butin : or et expérience.

Élite

Un combat plus dur, qui donne en plus une relique.

Boutique

Acheter des cartes, un soin, ou supprimer une carte du deck.

Repos

Se soigner, forger une rune sur une carte, ou en supprimer une.

Événement

Un texte narratif et trois choix aux conséquences chiffrées.

Boss

Le dernier étage. Le vaincre fait passer à l'acte suivant, avec une nouvelle carte.

À cela s'ajoutent deux nœuds spéciaux, plus rares : l'Autel des reliques, où l'on échange trois reliques contre une plus puissante, et la Forge de fusion, où l'on compacte les runes d'une carte.

Trois mécaniques structurent la progression :

  • L'expérience et les niveaux. Chaque ennemi vaincu donne de l'XP. À chaque niveau, un draft propose trois améliorations permanentes (points de vie, attaque, maîtrise d'armure, mana, critique…), parfois accompagnées d'un choix mythique.
  • La fusion de cartes. Trois exemplaires identiques d'une carte fusionnent en une carte de rareté supérieure, dont les effets sont multipliés.
  • Les reliques. Vingt-cinq objets passifs qui se déclenchent à des moments précis : début de run, début de combat, début ou fin de tour, carte jouée, ennemi tué.
À retenir

Le jeu est 100 % data-driven. Les cartes, les ennemis, les héros, les reliques, les événements et les runes de forge sont définis dans des fichiers JSON sous assets/data/. Ajouter une carte ne demande pas une ligne de Dart : on duplique une entrée JSON et on la modifie. Ce principe traverse tout le projet et explique une grande partie de son architecture.

3. La pile technique et pourquoi ces choix

Le projet repose sur quatre briques, chacune avec un rôle bien délimité.

BriqueVersionRôle dans Hero's Draft
FlutterSDK Dart ^3.11.4Toute l'interface hors combat : menus, carte du monde, boutique, deck, dialogues, HUD posé par-dessus l'arène
Flame^1.17.0Le moteur de jeu 2D. Uniquement l'arène de combat : cartes en main, héros, ennemis, animations, particules
Riverpodflutter_riverpod: ^2.5.1Tout l'état métier : santé, mana, deck, combat, inventaire, progression. Aucune règle du jeu ne vit ailleurs

La liste est courte, et c'est délibéré. Il n'y a ni générateur de code (freezed, json_serializable, riverpod_generator), ni bibliothèque de navigation, ni injection de dépendances tierce. Tout le fromJson / toJson est écrit à la main. C'est plus verbeux, mais cela veut dire qu'aucun code n'est généré : ce que vous lisez est ce qui s'exécute, et il n'y a pas d'étape de build supplémentaire.

La règle d'or du projet

Trois couches, jamais mélangées :

  • Flame rend — les composants lisent l'état et l'affichent ; ils ne le modifient jamais.
  • Riverpod décide — les contrôleurs portent toutes les règles ; ils ne connaissent ni widget ni animation.
  • Flutter habille — les widgets affichent et déclenchent ; aucune référence à Flame dans lib/ui/, aucun arbre de widgets dans un composant Flame.

Le chapitre 6 détaille cette séparation, qui est la clé pour se repérer dans le dépôt.

6. Installer et lancer le projet

Hero's Draft est un projet Flutter standard. Il n'y a ni script de build maison, ni étape de génération de code.

terminalbash
# 1. Récupérer les dépendances
flutter pub get

# 2. Lancer sur l'appareil par défaut
flutter run

# 3. Lancer toute la suite de tests
flutter test

# 4. Lancer un seul fichier de test
flutter test test/unit/combat_controller_test.dart

# 5. Lancer un seul test par son nom
flutter test --plain-name "description du test"

# 6. Analyse statique — doit être sans aucun problème
dart analyze

# 7. Construire un binaire
flutter build <apk|ios|web|windows|macos|linux>
Convention du dépôt

dart analyze doit renvoyer zéro problème avant de considérer un travail comme terminé. C'est écrit noir sur blanc dans CLAUDE.md, le fichier d'instructions du dépôt. Les règles viennent de package:flutter_lints/flutter.yaml :

analysis_options.yamlyaml
include: package:flutter_lints/flutter.yaml

Le jeu tourne sur toutes les plateformes Flutter ; les dossiers android/, ios/, web/, windows/, macos/ et linux/ sont tous présents. Une version web est déployée automatiquement à chaque tag (voir le chapitre 21).

Quiz — vérifiez vos acquis

1. Où sont définies les cartes du jeu ?

  • Dans lib/models/data/card_data.dart, en dur
  • Dans une base de données SQLite embarquée
  • Dans assets/data/cards.json et hero_cards.json
  • Elles sont générées procéduralement au démarrage
Réponse : le jeu est 100 % data-driven. card_data.dart ne contient que le modèle qui sait lire le JSON ; le contenu réel — 17 cartes globales et 6 cartes de classe — vit dans assets/data/.

2. Quel rôle Flame joue-t-il exactement dans ce projet ?

  • Il gère toute l'interface, y compris les menus et la boutique
  • Il ne gère que l'arène de combat : cartes en main, héros, ennemis, animations
  • Il gère l'état du jeu et les règles
  • Il sert uniquement à charger les images
Réponse : un unique GameWidget est monté dans game_screen.dart. Tout le reste — menus, carte du monde, boutique, HUD posé par-dessus l'arène — est du Flutter classique.

3. Combien d'étages compte une carte du monde, et que trouve-t-on au dernier ?

  • 10 étages, dont le dernier contient 3 nœuds Boss
  • 5 étages, dont le dernier contient 1 nœud Boss
  • 20 étages, sans boss
  • Un nombre aléatoire entre 8 et 15
Réponse : MapGeneratorService.generateMap a floors = 10 par défaut, et MapNodeGenerator force rowWidth = 3 au dernier étage, avec les trois variantes de récompense de boss.
